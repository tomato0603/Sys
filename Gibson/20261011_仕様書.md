## 2. 固定値と条件設定

### 2.1 固定値

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `DS_DNA_G_PER_MOL_PER_BP` | 650 | 二本鎖 DNA 1 bp の平均分子量 (g/mol)。慣用値 |
| `TOTAL_UL` | 20 µL | 反応の全量。常に 20 µL で、入力しない |
| `MASTER_MIX_FOLD` | 2 | G.A. Master Mix は 2×。Mix = 全量 ÷ 2 = 10 µL |
| `MIN_AMOUNT_UL` | 0.22 µL | ピペットで取れる最小の量 |

### 2.2 条件設定（判定の目安）

判定するだけで、Volume を勝手に決めたり変えたりしない。

| 項目 | 目安 | 画面の一覧に載せるか |
| --- | --- | --- |
| Vector の量 | 50–100 ng | 載せる |
| Insert / Vector（確認用 ng の比）、Insert が 200 bp 以上 | ×2–3 | 載せる |
| 同、Insert が 200 bp 未満 | ×5 以上 | 載せる |
| 合計 pmol、2–3 fragment | 0.02–0.5 pmol | 載せる |
| 合計 pmol、4–6 fragment | 0.2–1.0 pmol | 載せる |
| ピペットで取れる量（各 Volume） | 0.22 µL 以上 | 載せない（判定はする） |
| Insert と Vector の合計 | 10 µL 以下 | 載せない（超えると計算しない） |

- fragment の数は Vector と Insert の合計（1 fragment は無い）。Insert は 1–5 本なので 2–6 fragment。
- 200 bp ちょうどは「200 bp 以上」。範囲の端の値は満たしているとみなす。
- 倍数は小数第 2 位に丸めてから判定する。
- 画面の一覧は `GIBSON.guide()` が判定と同じ定数から作る（一覧と判定が食い違わない）。

## 3. A. 反応の組み立て

### 3.1 表

|  | Conc ng/µL | Length bp | pmol/µL | target pmols | 倍数 ×ng | Volume µL | 確認用 ng |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Vector | 入力 | 入力 | 計算 | 計算 | ×1 | 入力 | 計算 |
| Insert（名前は入力可） | 入力 | 入力 | 計算 | 計算 | 入力 | 入力 / 計算 | 計算 |
| G.A. M ×2 | | | | | | 10 | |
| miliQ | | | | | | 計算 | |
| Total | | | | 計算 | | 20 | |

「倍数」の列は「倍数から計算する」方式のときだけ出る。

### 3.2 計算

```
pmol/µL       = Conc × 1000 ÷ (Length × 650)
target pmols  = Volume × pmol/µL
確認用 ng     = Volume × Conc
G.A. M        = 全量 ÷ 2 = 10 µL
miliQ         = 全量 − G.A. M − (Insert と Vector の Volume の合計)
Total pmols   = target pmols の和（丸める前の値で足す）
Insert / Vector = Insert の確認用 ng ÷ Vector の確認用 ng
```

| 値 | 丸め |
| --- | --- |
| pmol/µL・target pmols・Total pmols | 小数第 4 位 |
| 確認用 ng | 有効数字 4 桁 |
| Volume・miliQ | 小数第 2 位 |
| Insert / Vector | 小数第 2 位 |

### 3.3 方式

| 方式 | 入力 | Volume |
| --- | --- | --- |
| Volume を入力する（既定） | 全断片の Conc・Length・Volume | 手入力。「おすすめの Volume」も使える |
| 倍数から計算する | 全断片の Conc・Length、Vector の Volume、各 Insert の倍数 | Vector は手入力、Insert は計算（読み取り専用） |

倍数から計算する方式（`GIBSON.amountsFromRatio`）:

```
Vector の ng      = Vector の Volume × Vector の Conc
目標 ng           = Vector の ng × 倍数
Insert の Volume  = 目標 ng ÷ Insert の Conc（小数第 2 位に丸める）
```

丸めで実際の ng は目標とずれるので、「計算確認」の表（目標 ng / Volume / 実際 ng /
倍数の目標と実際）を出す。判定は実際の ng で行う。

### 3.4 判定と表示

- 「計算・判定」ボタンで計算する。入力を書き換えたら、計算した欄・判定・おすすめを空に戻す。
- 判定の表: 項目 / 目安 / 実際 / 判定（OK・NG）。
- 条件設定に合っている数値は**青字**、外れている数値は**赤字**。
  対象は Volume（0.22 µL 以上か）、Vector の確認用 ng（50–100 ng か）、
  Insert の確認用 ng（倍数が目安内か）、Total pmols（範囲内か）。
- Insert と Vector の合計が 10 µL を超えたら計算せず、エラーを出す。
- Insert の名前: 行見出しが入力欄。空欄なら Insert（1 本のとき）/ Insert A, B, C…。
  Vector の名前は固定。名前は判定・おすすめ・出力・保存に使われる。
- 条件設定の一覧は折りたたみ欄で、最初は閉じている。

### 3.5 おすすめの Volume（`GIBSON.recommend`）

Conc・Length だけで動く（Volume は空欄でよい）。「Volume を入力する」方式のときだけ使える。

1. **すべての条件を満たす Volume を探す。** ピペットで取れる量（0.01 µL 刻み、0.22 µL 以上）を
   漏れなく調べるので、満たす Volume があれば必ず見つかる。
   見つかった中では、Vector が 75 ng（50–100 の中央）に近いもの、倍数が範囲の中央
   （×2.5。200 bp 未満の Insert は ×5）に近いものを選ぶ。
2. **見つからないとき**は、Vector の量・合計 pmol・Insert と Vector の合計 10 µL 以下・
   ピペットで取れる量を守り、Insert の倍数を下限（×2 / ×5）から同じ割合で
   できるだけ少なく下げた Volume を出す。外れた倍数は赤字で示す（この優先順位は利用者が承認）。
3. **それでも無いとき**は、満たせない条件を表示する。Vector がどの量でも 50–100 ng に
   ならないときは、希釈か濃縮を促す。

提案は表に勝手に入れない。「この Volume を表に入れる」を押したときだけ書き込み、計算・判定する。
候補はすべて丸めたあとの Volume で判定するので、表に入れても判定は変わらない。

### 3.6 数値の入力

全角数字と、日本語入力で「.」を押したときの「。」「．」を半角に読み替え、
「.8」は「0.8」として読む（`GIBSON.normalizeNumberText`）。欄から離れると表示もその形に直す。
名前の欄は読み替えない。

## 4. B. Tm値の計算

- 複数行の入力欄。1 行に 1 本。空白・数字・小文字は取り除いて読み、U は T として読む。
- 表: # / 配列 / 長さ (mer) / Tm (℃) / GC (%) / 注意。
- Tm はタカラバイオの簡易式（`PB.tmTakara` をそのまま呼ぶ）:
  `Tm (℃) = (A と T の数) × 2 + (G と C の数) × 4 − 5`。GC % は小数第 1 位。
- 簡易式の適用範囲は 25 mer 以下。超えた配列も値は出し、注意の列に適用範囲外と書く。
- A/C/G/T 以外の文字があればエラー（エンジンのメッセージのまま）。
- Tm 差: 2 本ならその 2 本の差。3 本以上なら Tm が最大と最小の組の差。

## 5. C. 結果の出力

- 計算済みの区画（A・B）だけを出す。各区画は最後に計算が成功したときの入力と結果。
  計算がエラーになった区画は出力から外す。
- **Markdown でコピー**: 出力日時・ツールの作製日時、A の表、計算確認（倍数の方式のとき）、
  条件設定の判定、B の表と Tm 差、計算式と前提。コピーに成功したら、その内容を
  折りたたみ欄に表示する。
- **印刷**: 同じ Markdown から、先頭の日時の行・見出し・表だけを取り出して印刷する
  （計算式と前提・文は印刷しない）。Cmd+P で印刷しても同じページになる。

## 6. 条件の保存

- 「いまの条件を保存」で、A と B の入力（方式・Insert の本数・各行の名前 / Conc / Length /
  倍数 / Volume・Tm の配列）を、任意の名前と保存日時を付けて保存する。結果は保存しない。
- 一覧は「保存した条件（n 件）」の折りたたみ欄（最初は閉じている）。各件は No.n（一覧での順番）・
  保存日時・名前・内容の要約で表示し、「読み込む」「削除」（確認あり）ができる。
- 保存先: `localStorage` のキー `gibson.conditions.v1`。保存できないときは
  「この画面を閉じると保存した条件は消えます」と表示して、画面の中だけで動く。

## 7. 修正リクエスト

- 要望を書いて「追加」を押すと、その時刻（YYYY-MM-DD HH:MM）付きで一覧にたまる。
- 「まとめてコピー」で全件を次の形式でコピーする。コピーしても一覧は消えない。

```
【Gibson 修正リクエスト】全 n 件
ツール: Gibson.html（作製 YYYY-MM-DD HH:MM）

[1] YYYY-MM-DD HH:MM
（要望）
```

- 入力欄に追加していない文章が残っていたら、コピーしたうえで注意を出す。
- 「一括削除」は確認ダイアログで OK を押したときだけ全件消す。
- 保存先: `localStorage` のキー `gibson.requests.v1`。
- 作製日時は `parts/gibson/ui.js` の `BUILT_AT`。画面を直すたびに更新する。

## 8. エラーの扱い

- 計算のエラー（`GibsonError` / `PbError`）は、メッセージをそのまま表示する。
  それ以外の例外は「予期しないエラー: 」を付けて表示する（握りつぶさない）。
- エラーのときは前回の結果を消す。

### 9.1 外に出す関数（`GIBSON`、画面が使うもの）

```
reaction({ fragments: [{ name, concentration, bp, ul }] })
    → { rows, mixUl, waterUl, dnaUl, totals: { pmol, ul, pmolOk }, checks, notes }
amountsFromRatio({ fragments: [{ name, concentration, bp, ul, ratio }] })
    → reaction の返り値 + { targets, vectorNg }
recommend({ fragments: [{ name, concentration, bp }] })
    → { satisfied, relaxed, result, message }
guide()                      → [{ label, target }]   条件設定の一覧
fragmentLabel(index, count)  → 名前が無い断片の名前
normalizeNumberText(text)    → 数値の文字列の読み替え
tmRows(text) / tmOf(seq) / tmDifference(a, b)
```

`plan`・`pmolFromNg`・`ngFromPmol`・`volumeUl`・`pcrConditions` は開発途中の機能の名残で、
エンジンには残っているが画面からは使わない。

## 11. 既知の制約・注意

- `parts/shared/engine.js` は MutaPrimer にも同じものがある。MutaPrimer 側の Tm の式を
  直したら、こちらにも反映すること。ずれを検出する仕組みは無い。
- 保存したリクエスト・条件は、そのブラウザの中にだけ残る。サイトデータを消すと消える。
  別のブラウザ・別のパソコンには引き継がれない。
- 2026-10-10 夕方より前に「倍数の方式」で保存した条件は Vector の量を ng で持っているため、
  読み込んだあと Vector の Volume を入れ直す必要がある。
- 開発時の確認に使った画面ではクリップボードとブラウザへの保存が使えなかったため、
  コピーと保存は差し替えた状態で動作を確かめた。印刷は、印刷用の見た目を画面に当てて確かめた。
